# AGENTS.md - Bough Git GUI Client

High-signal guidance for OpenCode agents working in this repository.

## Language

**All user-facing and in-repository text must be written in English** — including source code
comments, identifiers, documentation, commit messages, and any text inside the repo (docs, plans,
release notes, etc.) — **unless** it is explicitly a piece of text that has been localized/translated
into another language (for example, a translated UI string or a localized resource). Default to
English everywhere; write in another language only when translating an existing string into that
language on purpose.

## Commands & Directories

**Prerequisites:** Go 1.27+ and Node.js 22. Wails v3.0.0 is pinned as a Go tool in `app/go.mod` (`tool github.com/wailsapp/wails/v3/cmd/wails3`). Use `go tool wails3` from `app/`, not a globally installed CLI. The v3 Taskfiles call `wails3` from PATH, so run `make install-wails3` (builds the pinned CLI into `$(go env GOPATH)/bin`) when using the Make targets.

**All Wails development commands must be run from `app/` directory:**
```bash
cd app && go tool wails3 dev    # Full dev server with hot reload (Go + React)
cd app && go tool wails3 build  # Production binary → app/bin/Bough
cd app && go tool wails3 package  # .app bundle (macOS) / installer (Windows)
cd app && go tool wails3 generate bindings -ts -i -clean  # Regenerate frontend bindings
cd app && go mod download  # Download pinned Go dependencies
cd app && go mod tidy      # After changing Go dependencies
```

**Frontend-only commands (run from `app/frontend/`):**
```bash
cd app/frontend && npm install
cd app/frontend && npm run dev     # Vite dev server
cd app/frontend && npm run build   # Frontend build
cd app/frontend && npm test        # Vitest unit tests
```

**Make commands (run from root):**
```bash
make dev            # Wails dev server (cd app && go tool wails3 dev)
make build-wails    # Production Wails build (version via LD_FLAGS)
make generate-bindings  # Regenerate frontend bindings
make test           # Go backend tests with race detector
make test-frontend  # Frontend Vitest tests
make test-e2e       # Playwright E2E tests
make clean          # Remove build artifacts
```

## Architecture & Conventions

**Git Backend Split:**
- **Read operations**: Use `go-git` (history, diff, status, branches, refs)
- **Write operations**: Use `exec.Command git` (push/pull/fetch for auth, GPG, hooks)

**IPC Pattern (Wails 3):**
- Go methods on the `App` service auto-bind to frontend
- Frontend imports from `@bindings/bough/app` (generated by `wails3 generate bindings` into `app/frontend/bindings/`)
- Wails v3 runtime: `@wailsio/runtime` (`Events.On` for repo:changed, not the v2 `EventsOn`)
- **Never** use raw JSON over stdin/stdout

**Version Embedding:**
- `VERSION` is a Taskfile variable in `app/Taskfile.yml`, defaulting to
  `git describe --tags --always --dirty`; each platform Taskfile turns it into
  `-ldflags "-X main.version=$VERSION"`.
- The packaging tasks (`windows:package`, `darwin:package`, `linux:create:appimage`)
  rebuild the binary themselves. The version therefore has to come from that
  build (Taskfile default or `VERSION=...`, which CI passes as the pushed tag).
  Setting ldflags only on a previous `wails3 build` is not enough: the packaged
  app would report "Development build".

**Testing:**
- Go: `go test -race -cover ./...` (run from `app/`)
- Frontend: Vitest (run from `app/frontend`)
- E2E: Playwright tests in `app/frontend/tests/e2e/`

**Frontend Stack:**
- React 19 + TypeScript 5 + Vite
- Zustand for app state, TanStack Query v5 for async/cache
- Tailwind CSS 4 with CSS custom properties (design tokens in `app/frontend/src/index.css`)
- Monaco Editor for diff viewer, Radix UI for components

**Buttons (mandatory):**
- Use `app/frontend/src/components/shared/Button.tsx` for every application button; do not add raw `<button>` elements outside this shared component.
- Normal form/dialog actions must be visible at rest: use default `secondary`, explicit `primary` for the most important action, or `danger` for destructive confirmation. Do not make every action primary.
- Use `ghost` for flat toolbar, tab, menu and list controls; use `icon` for icon-only controls, with an accessible `aria-label` (and optionally a tooltip `title`). Preserve selected-state and row layout semantics.
- Button owns visual styles and hover/focus/disabled states in `app/frontend/src/index.css`. Do not create individual visual button recipes for normal actions or blanket CSS selectors targeting all native buttons. Local layout/size and selected-state styling for flat controls is allowed.
- Native props and React 19 refs pass through, so use Button directly inside Radix `asChild` triggers/close controls. The default type is `button`; specify `type="submit"` explicitly when needed.

**Design System:**
- **Principles:** clear and focused (no decorative elements), density with grace, working copy first,
  keyboard first (⌘K opens the Command Palette, all essential actions keyboard accessible).
- **Theme:** light and dark themes via CSS custom properties in
  `app/frontend/src/index.css`. Toggle by setting `data-theme="dark"` on `<html>`. Never hardcode
  colors — always use the design tokens (e.g. `--bg-content`, `--acc`, `--success`, `--danger`).
- **Typography:** Inter for all interface text; JetBrains Mono for hashes, filenames, diff content,
  and technical identifiers.
- **Icons:** Lucide (lucide-react) only, no emoji. Toolbar/sidebar icons 13px @ stroke-width 1.8;
  muted icons use `--text-sec`, primary actions use `--acc`.
- **Layout constants:** titlebar 40px · toolbar 44px · sidebar 200px · detail panel (history) 370px ·
  file list (changes) 240px · commit row 34px · sidebar item 24px · file item 26px · diff line 19px.
  Radii via `--r-sm`/`--r-md`/`--r-lg` (4/6/10px), window edge 12px.
- **Interactions:** hover transitions 100–120ms; input focus = `--acc` border + soft glow
  (`--acc-soft`, 2.5px ring); hunk actions start soft and fill on hover — stage `--success`,
  discard `--danger`, unstage `--acc`; flash notifications appear bottom-center in
  `--success`/`--danger`.

**Type System:**
Canonical Go types in `app/git/types.go` mirrored as TypeScript interfaces:
- `CommitNode`, `DiffFile`, `DiffHunk`, `DiffLine`, `FileStatus`, `WorktreeInfo`, `RepoStatus`

## Key Implementation Notes

**Commit Graph:**
- Rendered on `<canvas>` for performance
- DOM rows absolutely positioned in sync with canvas scroll
- Column/color layout computed in Go, returned as part of `CommitNode`

**Staging:**
- Per-hunk and per-line staging in Changes view
- `StageHunk`/`UnstageHunk`/`DiscardHunk` accept constructed patch strings
- Frontend `diffUtils.ts` builds minimal valid patches from selected lines

**Auto-update:**
- Sparkle 2 (macOS), WinSparkle (Windows), AppImageUpdate (Linux)
- EdDSA signatures required on all update artifacts
- Single appcast XML served from fixed URL

**Child Processes:**
- Create child processes with `sysproc.Command` / `sysproc.CommandContext`
  (`app/internal/sysproc`), never `exec.Command` / `exec.CommandContext`. Windows otherwise
  allocates a console window for each `git`/`ssh`/credential-helper run, which flashes on screen
  while a GUI app performs a Git action. The wrapper is a no-op outside Windows.
- `TestNoDirectExecCommand` fails when production code bypasses the wrapper, so this cannot be
  forgotten silently.

## Before Implementing Features

Check the relevant documentation in `docs/` and the code conventions in this file before adding new
features. Confirm your changes pass the [verification commands](#verification-commands) below before
moving on.

## Verification Commands

After changes, run in order:
1. `cd app/frontend && npm run build` (frontend build)
2. `cd app && go tool wails3 build` (full production build)
3. `make test && make test-frontend` (unit tests)
4. Check real Git repos (100+, 1000+, 10000+ commits)
5. Test cross-platform: macOS x86_64/ARM, Windows, Linux
